# AI SSD Training 首轮精选 Case 说明

## 选择范围

本说明基于 `docs/AI_SSD_TEST_PLAN.xlsx` 中的 16 个 Training Case。首轮优先选择能够覆盖不同数据访问形态、同时能快速定位 SSD 供数瓶颈的 Case；其余 Case 作为参数扩展、平台变体或长时确认。

## 首轮精选

| Case ID | 覆盖场景 | 选择理由 |
| --- | --- | --- |
| AI-TRN-001 | 大文件连续读取 | 建立训练数据供给的基线，先确认 SSD 在低压力连续访问下是否稳定，便于解释后续小文件、随机和并发结果。 |
| AI-TRN-004 | JPEG 小文件访问 | 覆盖消费级 AI PC 常见的小文件、目录和元数据压力，可直接观察 IOPS、P99 和文件访问速率。 |
| AI-TRN-006 | 中等对象随机/混合访问 | 补充连续读取之外的随机访问和 shuffle 行为，验证访问位置变化后吞吐与延迟是否明显恶化。 |
| AI-TRN-010 | Parquet 行组/列读取 | 覆盖列式数据的非连续读取，验证只读取部分列或行组时的放大效应、P99 和有效供数能力。 |
| AI-TRN-014 | 并发扩展与饱和点 | 找到从低并发到 SSD/CPU 饱和的拐点，避免只用单一并发度判断产品能力。 |
| AI-TRN-016 | 缓存与路径有效性 | 确认 warm/cold/direct 等控制条件确实产生不同的物理读行为，防止把系统缓存命中误判为 SSD 性能。 |

## 推荐执行顺序

1. **AI-TRN-016**：先校验数据路径、冷/热缓存控制和 PhysicalDisk 读字节证据。
2. **AI-TRN-001**：建立大文件连续供给基线。
3. **AI-TRN-004**：验证小文件和元数据压力。
4. **AI-TRN-006**：加入随机/混合访问，观察访问模式变化的影响。
5. **AI-TRN-010**：验证列式读取和有效数据比例。
6. **AI-TRN-014**：在上述访问形态确认后做并发扩展，定位饱和点。

每个 Case 的表格步骤、时长、命令和通过标准见 [AI_SSD_TRAINING_CASE_PLAN.xlsx](AI_SSD_TRAINING_CASE_PLAN.xlsx)。对应的可执行入口为 [ai_ssd_training_case_runner.py](../tools/ai_ssd_training_case_runner.py)。

## 暂不纳入首轮的 Case

AI-TRN-002、003、005、007、008、009、011、012、013、015 主要是已覆盖访问形态的加速器、数据规模、batch、线程或长时变体。首轮完成后，再根据瓶颈位置选择这些变体，可以减少重复执行并保留针对性确认。
